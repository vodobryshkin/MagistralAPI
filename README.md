# Magistral API

## Описание проекта

Бэкенд службы доставки, написанный на Spring Boot. Приложение реализует основную логику, необходимую для работы службы доставки: регистрацию пользователей и компаний, аутентификацию, подтверждение аккаунта через электронную почту, расчёт стоимости доставки и оформление заказов.

При создании заказа генерируется документ с заявкой на доставку, который отправляется на почту и сохраняется в объектное хранилище. Помимо обычных заказов есть отдельная форма для доставки чемоданов, которая внутри приложения обрабатывается через общий механизм создания заказа.

Инфраструктура для локального запуска описана в `compose.yml`. Параметры подключения к внешним сервисам и остальные настройки приложения находятся в `src/main/resources/application.yml`.


### Основные возможности

- Регистрация физических лиц.
- Регистрация пользователей, представляющих компанию.
- Подтверждение аккаунта через электронную почту.
- Вход по почте и паролю.
- Аутентификация с помощью двух JWT-токенов: короткоживущего access и долгоживущего refresh.
- Получение информации о текущем пользователе.
- Предварительный расчёт стоимости доставки без создания заказа.
- Расчёт стоимости доставки чемодана.
- Определение региона по адресу с помощью DaData.
- Оформление обычного заказа на доставку.
- Оформление заявки на доставку чемодана.
- Идемпотентное создание заказов через заголовок `Idempotency-Key`.
- Генерация DOCX-документа с заявкой после оформления заказа.
- Отправка писем и обработка документов через RabbitMQ.
- Хранение сформированных документов в MinIO.

## Запуск

1. Склонировать к себе репозиторий.
2. В корне проекта создать `.env`-файл с переменными окружения, которые используются в `application.yml` и `compose.yml`.
3. Запустить необходимую инфраструктуру с помощью

```shell
docker compose up -d
```

Docker Compose поднимет PostgreSQL, Redis, RabbitMQ и MinIO.

4. Запустить приложение:

```shell
./mvnw spring-boot:run
```

Для сборки приложения также можно использовать:

```shell
./mvnw clean package
```

## Swagger

Документация API генерируется через OpenAPI-аннотации непосредственно из кода. Для просмотра сгенерированной Swagger документации после запуска бэкенда нужно перейти по адресу:

`http://localhost:8080/swagger-ui/index.html#/`

Через Swagger можно посмотреть доступные эндпойнты, форматы запросов и возможные ответы API. 

## Хранилище документов

Документы по оформленным заказам хранятся в MinIO.

Для просмотра документов при локальном запуске нужно:

1. Запустить бэкенд и MinIO.
2. Перейти по адресу `http://localhost:9001/login`.
3. Ввести логин и пароль MinIO из `.env`-файла.
4. Открыть основной bucket с документами.

Документы распределяются по дате создания и имеют следующую структуру:

```text
orders/<год>/<месяц>/<день>/<имя файла>
```

## Подтверждение аккаунта

После регистрации пользователь изначально имеет неподтверждённый аккаунт. Для подтверждения на его почту отправляется письмо со ссылкой, содержащей одноразовый токен.

Если письмо не пришло, его можно запросить повторно. На повторную отправку действует ограничение по времени.

После успешного подтверждения пользователю выдаются новые access- и refresh-токены уже с правами подтверждённого пользователя.
